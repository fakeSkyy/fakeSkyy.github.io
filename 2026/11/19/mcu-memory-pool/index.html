在MCU实现一个简单的内存池

什么是内存池？

内存池（Memory Pool），又被称为固定大小区块规划（fixed-size-blocks allocation），允许程序员以类似 C语言 的 malloc 或是 C++ 的 new 操作数进行动态的存储器规划。对于其它动态存储器规划的实践来说，因为会变动存储器区块大小导致的碎片问题，导致在实时系统上受限于性能因此，根本无法使用。内存池提供了一个更有效率的解决方案：预先规划一定数量的存储器区块，使得整个程序可以在执行期规划 (allocate)、使用 (access)、归还 (free) 存储器区块。

为什么不使用c库的malloc？

稳定性，可控性

首先，我们知道定义在不同作用域或使用不同关键字修饰的变量，其所存储的位置是不同的
STM32 链接器对SRAM主要划为以下几个段：

区域 主要用途 示例
.data 有非零初始值的可修改全局变量、静态变量 int a = 10;
.bss 未显式初始化或初始化为零的全局变量、静态变量 int b;、static int c = 0;
堆 Heap 动态分配内存 malloc() 申请的空间
栈 Stack 函数调用现场、需要落到内存中的普通局部变量等 函数内的 int x;
自定义区域（可选） 不清零的数据、DMA 缓冲区等 .noinit、自定义 section

我们使用malloc 就是在堆（heap）去申请内存空间。这样做本身没什么问题，但对于追求稳定的嵌入式系统，我们没办法很好的监测堆的使用情况，也无法去处理分配失败的情况。虽然基本不会分配失败

一般情况，我们自己实现的内存池，就是直接定义一个超级大的全局数组，而全局变量是存放在.bss或.data段的（内存池一般初始化为0，所以在.bss段），这两个段的空间大小在编译期就可以确定。之后，我们只在自己定义的大数组内存池中申请内存，且申请函数和释放函数都由我们自己定义，所以更加稳定可控

我们刚刚提到了字节对齐，为什么实现内存池需要字节对齐？

先简单解释一下字节对齐：

计算机中内存大小的基本单位是字节（byte），理论上来讲，可以从任意地址访问某种基本数据类型，但是实际上，计算机并非逐字节大小读写内存，而是以2，4，或8的倍数的字节块来读写内存，如此一来就会对基本数据类型的合法地址作出一些限制，即它的地址必须是2，4或8的倍数。那么就要求各种数据类型按照一定的规则在空间上排列，这就是对齐

再回到刚刚的问题，为什么实现内存池需要字节对齐：

因为 CPU 访问某些类型时，要求地址是特定数值的整数倍。例如，STM32上的uint32_t通常要求地址按 4 字节对齐。
不对齐可能导致访问变慢，某些指令或配置下甚至会触发硬件异常。
所以内存池必须保证：块头和返回给用户的数据地址，都满足相应类型的对齐要求。

我们定义的内存池一般都是使用uint8_t类型，但uint8_t是1字节对齐，假设 uint8_t buffer[100] 的起始地址是 0x20000003，我们要在这个buffer中存一个float或double，而float是4字节对齐，double是8字节对齐，为了满足不同数据类型的对齐需求，我们的内存池使用8字节对齐，因为2*4=8。当然，在STM32上也没有超过8字节的数据类型了。
